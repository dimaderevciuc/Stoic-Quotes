## 1. Product vision

A privacy first Android app (Google Play only) that helps people in hard moments with Stoic philosophy.

- **Main screen (Situation):** the user describes their situation in free text. The app returns a small batch of relevant Stoic quotes, each with an explanation and how it applies to the situation, plus a short practical exercise.
- **Second tab (Explore):** random quotes, shuffled with no repeats until all have been seen.
- **Third tab (Favorites).**
- **About and Safety screen:** replaces the current non-functional Contacts screen.

### Hard constraints
1. **Size:** release APK for arm64 under **30 MB** (target), never above 100 MB. No generative LLM is bundled in the APK.
2. **Offline and private:** the core feature works fully offline. No user text ever leaves the device. No analytics, no tracking SDKs.
3. **Android only** for now (minSdk to be decided in Phase 0, see notes).
4. **Copyright:** only public domain translations (see Phase 1).
5. **Safety:** crisis detection runs before any matching or AI (see Section 8).

## 5. Phase 1: Quote corpus pipeline

### Sources (public domain translations only)
- Marcus Aurelius, *Meditations*, translated by George Long.
- Seneca, *Moral Letters to Lucilius*, translated by Richard M. Gummere (Loeb, 1917 to 1925, available on Wikisource).
- Epictetus, *Discourses* and *Enchiridion*, translated by George Long (or W. A. Oldfather 1925 if clearly public domain).

Verify the translator and publication year from each file's header and record it in the data. **Do not use** Gregory Hays, Robin Hard, Robin Waterfield, Martin Hammond, or any other modern translation.

If the network blocks a download, tell Dima which URL to download manually and where to put it (`pipeline/data/raw/`).

### Steps
1. `download.py`: fetch the texts, store raw files, keep a `sources.json` with URL, translator, year, and SHA-256 of each file.
2. `split.py`: strip boilerplate (Gutenberg headers and footers), split into passages with exact citations (for example Meditations 4.3, Letter 13.4, Enchiridion 1).
3. `curate.py`: select quote worthy lines from the passages. You (Claude Code) do the curation yourself, in batches of passages, and write the candidates to `data/curated/quotes_<work>.jsonl`.
4. Validation rules (enforced in code and tests):
   - The quote text must be an **exact substring** of its source passage (after whitespace normalization). This prevents invented or misattributed quotes.
   - Unique `id` (format `ma-4-3-a`, `sen-13-4-a`, `epi-ench-1-a`).
   - No near duplicates (normalized text plus a similarity check).
   - Length between 40 and 400 characters.
5. Each quote gets metadata, written by you and reviewed by Dima with `review.py`:

```python
class Quote(BaseModel):
    id: str
    text: str
    author: Literal["Marcus Aurelius", "Seneca", "Epictetus"]
    work: str
    citation: str            # e.g. "Meditations 4.3"
    translator: str
    year: int
    context: str             # surrounding passage, shown in the app
    explanation: str         # 1 to 3 plain sentences, what it means today
    themes: list[str]        # e.g. control, death, anger, adversity
    needs: list[str]         # e.g. calm, courage, perspective, acceptance
    reviewed: bool = False
```

6. `review.py`: a small `typer` CLI that shows one entry at a time and lets Dima approve, edit, or reject it. Only `reviewed=True` entries go to the app.
7. Port the 63 existing quotes: keep the ones that can be traced to a public domain source, flag the rest for Dima.

**Expected output:** 500 or more validated quotes in `data/curated/`, all tests pass.

**CHECKPOINT 1:** show counts per author and theme, plus 10 random samples.

## 6. Phase 2: On-device embeddings (Model2Vec, pure Dart)

### Technology
- **Model2Vec** static embeddings, model `minishlab/potion-base-8M` (MIT license). Each token has a fixed vector, a sentence vector is the mean of its token vectors, then L2 normalized. No neural network runs on the phone, so no native runtime is needed.
- Check the model card and the `model2vec` library source for the exact inference steps (tokenizer type, normalization, pooling, any weighting) and replicate them exactly.

### Steps
1. `embed.py`: load the model, embed every quote (use `text` plus `explanation`, test whether this helps retrieval) and every situation example phrase.
2. Export for the app:
   - The tokenizer vocabulary and rules (from `tokenizer.json`).
   - The token vector matrix quantized to int8 with one float32 scale per row.
   - The quote and situation embeddings (int8 plus scale), stored in `content.db` or a binary file.
   - Report the total size. Target: under 12 MB.
3. Prune the vocabulary only if it is safe (measure the quality impact first).
4. Create `data/golden/parity.json`: 30 test sentences with the expected top 5 quote IDs and the cosine scores from Python.
5. Dart side in `lib/core/embedding/`:
   - Tokenizer that matches the Python tokenizer exactly (unit tests against Python token IDs).
   - Embedder (lookup, mean, normalize).
   - Search: brute force cosine similarity, top k. Run it in an isolate if it takes over 16 ms.
6. Dart tests: same top 5 IDs as `parity.json` for all 30 sentences, scores within 0.01.
7. Retrieval quality check in Python: write 50 realistic situations with the quotes a human would expect, measure recall@5. If it is poor, report options (another potion model, fine tuning a Model2Vec model on situation to quote pairs) before doing anything.

**Expected output:** Dart search returns the same results as Python, in under 50 ms on a mid range phone.

**CHECKPOINT 2:** show the size report, parity results, and recall@5.

## 7. Phase 3: Situation library (pre-written, human reviewed)

The main screen shows reflections that were written ahead of time and reviewed by a human, matched to the user's text. Nothing is generated on the phone in this phase.

```python
class Situation(BaseModel):
    id: str                       # e.g. "rejected-after-interview"
    title: str                    # short, shown in the UI
    category: str                 # work, relationships, loss, health, self, ...
    example_phrases: list[str]    # 6 to 10 ways people describe it
    quote_ids: list[str]          # 3 to 5 quotes from the corpus
    applications: dict[str, str]  # quote_id -> how this quote applies here
    exercise: str                 # one concrete Stoic practice, 2 to 4 steps
    is_sensitive: bool            # abuse, grief, illness: extra care
    reviewed: bool = False
```

1. Draft a taxonomy of about 150 situations across categories. **CHECKPOINT 3a:** Dima approves the list before writing content.
2. Write the content (you write it, Dima reviews with `review.py`).
3. Writing rules:
   - Never suggest that someone should accept abuse, mistreatment, or danger. "What is in your control" must include seeking help, setting boundaries, and leaving.
   - Never present Stoicism as a replacement for medical or psychological care.
   - Plain, warm, short language. No moralizing.
4. A situation embedding is the mean of its example phrase embeddings. Matching: compare the user's text against both situations and quotes. Show the best situation (if similarity is above a threshold) plus the top quotes. If nothing is above the threshold, show the top quotes with their general explanations only.
5. Tune the thresholds with the 50 test situations from Phase 2.

**Expected output:** a reviewed situation library in `content.db`.

**CHECKPOINT 3b:** show 5 full examples and the threshold tuning results.
